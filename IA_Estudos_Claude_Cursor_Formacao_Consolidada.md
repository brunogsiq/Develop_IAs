A formação foi construída para desenvolver domínio prático de Inteligência Artificial aplicada a:

- Engenharia de Software;
- QA Manual;
- QA Automation;
- Desenvolvimento Front-end;
- Desenvolvimento Back-end;
- Banco de Dados;
- Git e GitHub;
- DevOps;
- CI/CD;
- Docker;

- Agentes de IA;
- MCP;
- Claude;
- Claude Code;
- Cursor;
- Integrações com ferramentas externas;
- Portfólio profissional.

O objetivo final não é apenas "usar IA".

O aluno deverá aprender a:

1. entender IA e LLMs;
2. criar prompts de alta qualidade;
3. escolher a ferramenta adequada para cada problema;
4. utilizar Claude profissionalmente;
5. utilizar Cursor profissionalmente;

7. desenvolver aplicações completas;
8. testar aplicações manualmente e de forma automatizada;

10. trabalhar com ferramentas de gestão como Jira e Trello;
11. configurar pipelines de CI/CD;
12. utilizar Docker;
13. integrar IA ao fluxo de Engenharia de Software;
14. produzir documentação técnica;
15. construir um projeto de portfólio completo.

# 8. Exemplo de Prompt Ruim, Bom e Excelente

## 8.1 Prompt Ruim

```text
Faça casos de teste para login.
```

### Problemas

- não define contexto;
- não define objetivo;
- não define formato;
- não define papel da IA;
- não informa requisitos;
- não impõe restrições;
- aumenta a chance de resposta genérica.

---

## 8.2 Prompt Bom

```text
Atue como um QA Sênior.

Crie casos de teste em BDD para uma tela de login contendo os campos E-mail e Senha.

Considere cenários positivos e negativos.
```

### Melhorias

- papel definido;
- objetivo definido;
- contexto mínimo;
- formato definido;
- escopo delimitado.

---

## 8.3 Prompt Excelente

```text
Atue como um QA Sênior especializado em Engenharia de Software,
Análise de Requisitos e Planejamento de Testes Manuais.

Analise exclusivamente a documentação fornecida.

Não invente regras, fluxos, mensagens, validações, permissões,
persistências ou comportamentos que não estejam documentados.

Caso exista alguma lacuna ou ambiguidade, registre-a como
"Ponto de Atenção".

Elabore cenários de teste em BDD utilizando:

Dado
E
Quando
Então
E

Inclua somente cenários suportados pela documentação fornecida.

Considere:

- Cenários positivos;
- Cenários negativos;
- Regras de negócio;
- Critérios de aceite;
- Obrigatoriedades documentadas;
- Navegação documentada;
- Mensagens documentadas;
- Limites documentados;
- Rastreabilidade entre requisito e cenário.

Ao final, revise todos os cenários para garantir que nenhum
comportamento não documentado tenha sido assumido.
```

## 8.4 Exercício

Executar os três prompts no mesmo modelo.

Comparar:

- precisão;
- nível de detalhe;
- aderência ao requisito;
- quantidade de suposições;
- capacidade de reutilização.

Depois repetir no:

- ChatGPT;
- Claude;
- Gemini.
